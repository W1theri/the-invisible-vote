# THE INVISIBLE VOTE

**GitHub Pages + Supabase · онлайн-опрос и автономная демонстрация**

Участники открывают одну ссылку на своих телефонах, получают A/B-интерфейс и отправляют ответы в общую базу. Исследователь входит в защищённую панель и видит завершённые анкеты со всех устройств.

## Что находится в проекте

- `index.html`, `src/` — онлайн-интерфейс EN/RU и исходный код.
- `config.js` — только публичные URL и publishable key **нового** Supabase-проекта опроса.
- `supabase/schema.sql` — приватные таблицы и серверные RPC с ограниченным доступом.
- `supabase/add-researcher.sql` — выдача исследовательского доступа конкретному постоянному пользователю Auth по UUID.
- `offline.html` — прежний полностью автономный сайт со встроенными CSS/JS; работает двойным щелчком без интернета.
- `scripts/build.mjs` — сборка статических файлов и локального SDK, без CDN.
- `.github/workflows/pages.yml` — тесты базы, сборка и публикация GitHub Pages.
- `tests/` — проверки SQL и браузерные сценарии.
- `documentation/OFFLINE_GUIDE.md` — подробное описание философии, этики, требований Endterm Guide и автономной версии.
- `VERIFICATION.md` — область и результаты проверок онлайн-версии.

Существовавший ранее Supabase-проект другого сайта **не используется**. Все объекты опроса размещаются в отдельном проекте. Не запускайте SQL опроса в базе другого приложения.

## Локальный запуск

Нужен Node.js 22 или новее.

```sh
npm ci
npm run build
npm run preview
```

Откройте `http://127.0.0.1:4173`. Онлайн-сайт использует файлы из `dist/`; установка Node нужна для разработки, но не участникам опубликованного сайта. Корневой `index.html` является шаблоном сборки, поэтому для онлайн-версии используйте preview или опубликованный адрес. Для полностью автономного запуска откройте `offline.html` двойным щелчком.

Без правильного подключения к базе кнопка сбора ответов недоступна. Приложение явно сообщает об отсутствии настройки и предлагает офлайн-демонстрацию. Сбой сети не переключает реальные ответы в локальный режим и не выдаёт ложное сообщение об успешной отправке.

## Настройка отдельного Supabase-проекта

Для этого экземпляра опроса выбран новый проект `kslzzgifzbxukuabrqjj` (Ayo). Публичная конфигурация уже записана в `config.js`. При развёртывании своей копии используйте собственный **отдельный** проект.

1. В SQL Editor нового проекта выполните весь `supabase/schema.sql`.
2. В **Authentication → Sign In / Providers** включите **Allow anonymous sign-ins** и сохраните. Email-подтверждение постоянных аккаунтов отключать не нужно.
3. В **Authentication → Users → Add user → Create new user** создайте постоянный аккаунт исследователя. Email и пароль вводит владелец. Для созданного вручную аккаунта можно использовать Auto confirm user. Пароль в файлы проекта не записывается.
4. Скопируйте UUID этого пользователя. Подставьте его вместо нулевого UUID в `supabase/add-researcher.sql` и выполните запрос в SQL Editor. Анонимному участнику исследовательский доступ не выдаётся.
5. В `config.js` укажите Project URL и **publishable** key. Секретные `sb_secret_*` и `service_role` ключи сюда добавлять нельзя. Клиент отвергает ключи неподходящего типа.

Клиентская конфигурация публична по назначению; защиту обеспечивают серверные функции и права базы, а не скрытие URL или ключа. В новом проекте используется схема `iv_private`, которая не открывается через Data API. Прямого доступа `anon`/`authenticated` к таблицам нет; RLS включена. API предоставляет только узкие функции текущего участника и проверяемые функции исследователя.

## Публикация через GitHub Pages

Репозиторий этого проекта: `https://github.com/W1theri/the-invisible-vote`.

1. Загрузите исходники в ветку `main`.
2. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Workflow **Test and deploy GitHub Pages** проверит SQL, соберёт `dist/` и опубликует его.
4. Опубликованный адрес этого экземпляра: `https://w1theri.github.io/the-invisible-vote/`.

Обычному участнику отправляйте именно адрес сайта. Исследовательский вход открывается через **Researcher access** или ссылку с `#research` в конце. Опубликованный сайт и код могут быть публичными; сами ответы остаются в базе и доступны только авторизованным исследователям.

Для смены публичной конфигурации можно обновить `config.js` либо задать Repository **Variables** `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`. Workflow читает только эти публичные переменные; серверные секреты ему не требуются.

## Работа участника

1. Уведомление и добровольное согласие.
2. После согласия Supabase создаёт анонимную техническую сессию, без запроса имени, email или пароля.
3. Сервер назначает A или B. Название группы на экране голосования не показывается.
4. Голос фиксируется в базе и блокируется. Повтор того же запроса безопасен; изменить вариант после сохранения нельзя.
5. Два обязательных вопроса: осознанность влияния и уверенность 1–5. Причина необязательна, до 500 символов.
6. Только завершённая анкета включается в статистику. Затем раскрываются обе версии, экспериментальная подсказка и философские вопросы.
7. **Delete my response** удаляет голос и поля анкеты из общей базы. Остаётся минимальная техническая отметка участия для запрета повторного ответа в этой сессии. Ранее экспортированные копии удалить с сайта нельзя.

Анонимные токены сохраняются в браузере, чтобы продолжить анкету и отозвать ответ после обновления. После очистки браузера или смены устройства этот доступ теряется. Проверки «один реальный человек — один ответ» без дополнительной идентификации здесь нет. Не проходите реальное исследование повторно.

При проблеме сети показан последний подтверждённый экран и кнопка **Check saved session / reconnect**. Серверные действия идемпотентны: повторная отправка после неясного сетевого исхода не добавляет вторую строку. До подтверждения базы интерфейс не заявляет об успешном завершении.

## Панель исследователя

Вход требует email/пароля **постоянного пользователя Supabase Auth** и наличия его UUID в `iv_private.researchers`. Пароля, зашитого в JavaScript, нет. Проверка доступа выполняется на сервере для каждой административной функции. Auth-сессия исследователя хранится в sessionStorage вкладки, отдельно от анонимной сессии участника.

На панели доступны:

- Общая статистика завершённых анкет, A/B-сравнение, осознанность, уверенность и распределение голосов.
- Размеры групп, разница в процентных пунктах и осторожная описательная интерпретация.
- Таблица анонимных результатов, CSV с BOM и защитой от формул, архив JSON.
- Обновление каждые 10 секунд, пока исследователь смотрит реальные результаты в активной вкладке; время последнего подтверждённого снимка и предупреждение при сбое связи.
- **Pause new participation / Reopen participation**: пауза запрещает новые назначения, но не мешает уже начавшим участникам завершить анкету или отозвать ответ.
- **Copy participant link** и локально генерируемый QR-код на опубликованном HTTPS-сайте. Локальные адреса preview не выдаются за доступную со смартфонов ссылку.
- **Live experiment**, полноэкранный проектор и раскрытие эксперимента.
- Очистка всех реальных ответов с подтверждением. После неё новый набор приостанавливается, счётчики сбрасываются.

Функция **Start a new anonymous session** нужна только для общего устройства под наблюдением. Она завершает предыдущую техническую сессию; завершённый ответ остаётся в базе, но предыдущий участник теряет доступ к его отзыву на этом устройстве. С телефона участник начинает самостоятельно по общей ссылке.

### Тесты и демоданные

**Test Group A / Test Group B** работают только как локальные изолированные предпросмотры и не вызывают серверное назначение или запись ответа. **Generate 40 Demo Participants** создаёт по 20 синтетических записей на группу в localStorage. В обеих группах вероятность выбора библиотеки 50%; преимущество B не заложено.

Переключатель **Real Data / Demo Data** применяется к диаграммам, таблице, CSV/JSON и проектору. Демоданные не попадают в реальную базу. Импорт в онлайн-панели разрешён только для синтетического JSON. Реальный JSON — архив результатов, а не способ подменить серверные назначения; восстановление реальной базы выполняет её администратор. Полный локальный импорт/экспорт реальных офлайн-записей остаётся в `offline.html` и не загружает их в онлайн-базу.

## Серверная модель и ограничения

`iv_start` блокирует единственную строку состояния исследования на время транзакции. При равных счётчиках группа выбирается случайно; затем предпочтение отдаётся меньшей группе. Это сохраняет баланс назначений при одновременных стартах с телефонов. Отказы и незавершённые анкеты могут нарушить баланс завершённых групп. Счётчики назначений сохраняются после отзыва.

Первичный ключ сессии — внутренний Auth UUID; отдельный случайный `public_id` используется в экспортах. Участник не передаёт в RPC чужой ID и не выбирает свою реальную группу. Группа, состояние, язык и ответ связаны на сервере. Лимит — 10 000 назначений до начала нового набора.

```text
Library Choice Rate(g) = Library Votes(g) / Completed Surveys(g) × 100
Difference = Library Choice Rate(B) − Library Choice Rate(A)
Confidence(g) = Sum of Confidence(g) / Completed Surveys(g)
```

Пустые группы показывают тире. Разница долей не является доказательством причинности или статистической значимости. При малой выборке это предварительные наблюдения. Формулировка про разницу менее 5 п. п. — только описательная подсказка, не статистический критерий.

## Приватность и проведение исследования

Анкета не запрашивает имя и контакты, но онлайн-инфраструктура создаёт технические Auth-идентификаторы и может хранить журналы соединений, включая IP и время. Поэтому интерфейс не обещает абсолютную техническую анонимность. Не вводите личные данные в свободный текст. Экспорт не включает Auth UUID, email или пароли; идентификатор исследовательского аккаунта хранится отдельно.

Не отключайте RLS и не добавляйте общие политики чтения. Сервер проверяет постоянный аккаунт и список исследователей; пользовательские metadata не дают административных прав. Секретные ключи не нужны браузеру или GitHub Pages.

Перед публичным набором проверьте ограничения Supabase Auth на число анонимных регистраций с одного IP, особенно для аудитории в одной университетской Wi-Fi сети. У провайдера есть лимиты и защита от злоупотреблений; клиентский запрет повторного голоса не защищает от массового создания новых браузерных идентичностей. Если включаете CAPTCHA в Supabase, нужно дополнительно подключить её виджет и captchaToken в клиенте: текущая версия не включает CAPTCHA и не обходит её. Сведения о CAPTCHA и тарифах проверяйте по актуальной документации провайдера.

У бесплатного Supabase-проекта возможна пауза после периода неактивности; перед защитой проверьте, что база активна. Регулярно сохраняйте JSON и CSV: ручной экспорт не равен автоматической резервной копии всей инфраструктуры. Определите сроки удаления данных и экспортированных копий в команде.

## Философская и социальная основа

**Social Problem:** digital interfaces may shape students' choices without their full awareness.

**Research Question:** to what extent can interface design influence the decisions students perceive as autonomous?

**Kant:** autonomy, independent judgment and rational choice. **Foucault:** subtle power relations and the conditions through which behavior is guided. Из интерфейсного эксперимента нельзя делать вывод о внутренней свободе конкретного человека. Проекторный тезис — формулировка проекта, не дословная цитата философа.

Этические вопросы: допустимо ли скрыто влиять на выбор; возможно ли осмысленное согласие при временном сокрытии части методики; как совместить убеждение и автономию? Защита: добровольность, предупреждение до участия, низкорисковый гипотетический выбор, объяснение и раскрытие непроверенности Popular choice, возможность отзыва, ограничение доступа к данным.

**Digital Freedom Guide:** сделать паузу перед выделенной рекомендацией; сравнить видимость всех вариантов; проверить социальные подсказки; найти малозаметные альтернативы; сформулировать собственные доводы до подтверждения.

Подробная связь с критериями Endterm Guide и сценарий 7–10-минутной защиты сохранены в `documentation/OFFLINE_GUIDE.md`. Демонстрационные и тестовые ответы не заменяют собственные данные команды.

## Проверки и дальнейшая разработка

```sh
npm test
npm run build
npm run test:browser
```

Браузерные тесты требуют установленного Microsoft Edge. Они используют отдельную локальную PGlite/PostgreSQL базу и имитацию Supabase Auth/HTTP, не отправляя тестовые ответы в рабочую базу. Настоящее облачное соединение проверяется отдельно после настройки проекта. PGlite имеет один backend и не заменяет нагрузочное тестирование нескольких настоящих серверных соединений.

Для большой публичной кампании потребуются дополнительные меры от массовых регистраций, мониторинг нагрузки, согласованная политика хранения и проверка требований университета. В текущем учебном масштабе сохраняйте добровольность и не трактуйте удобную выборку как репрезентативную для всех студентов.
